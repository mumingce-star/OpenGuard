# OpenGuard 前端优化总结

依据《OpenGuard 前端优化与实施建议（前端负责人版）》实施。范围为前端 P0 闭环及 P1 证据阅读器、演示控制和图谱；保留首页品牌动效。实现阶段已完成本地验收；2026-09-03 用户授权通过 feat/xzb-frontend 分支与 PR #1 同步，main 仍需团队审查后合并。

## 已完成

| 位置       | 优化内容                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| 新建扫描   | GitHub 格式/访问校验分离，ZIP 选择/拖放/替换/移除、非空与可配置大小预检；重复提交保护和明确失败提示               |
| 数据模式   | mock/api 显式区分，环境变量生效；真实接口失败不回退演示；进入工作台不自动加载历史任务                             |
| 任务进度   | 等待、执行、完成、失败和部分失败统一；按阶段而非虚构百分比展示；任务编号固定，刷新查询不重复创建                  |
| 概览统计   | 资源、全部风险、待处理风险、许可待确认均由完整快照派生；指标和分布可跳转对应筛选                                  |
| 风险中心   | 严重度、状态、资源类型、搜索组合筛选；详情通过 scanId/riskId 寻址；返回保留筛选和滚动位置；非法编号有空态         |
| 判断可信度 | 扫描事实、规则判断、AI 解释分层；人工处理与复扫验证独立；移除固定准备度、预期加分和置信度展示                     |
| 证据阅读器 | 项目代码/许可原文/判断依据分类，编号、来源、文件位置、行号与高亮、引用复制；缺失原文不补造                        |
| 资源清单   | 搜索、类型、风险、许可待确认组合过滤；详情抽屉与相关风险；CSV 标明并遵循当前筛选范围                              |
| 报告       | 执行摘要、风险清单、第三方资源、模型数据集、整改、证据附录六章；完整 JSON 与浏览器打印/PDF                        |
| 图谱       | React Flow 按风险聚焦，缩放、平移、重置，节点打开同一阅读器，提供键盘按钮入口；图谱代码按页懒加载                 |
| 演示与投屏 | 6 个固定异常/正常场景，可重播、跳过等待；投屏开关与演示数据模式独立                                               |
| 可读性     | 工作台正文 14px、辅助文字 12px、代码 13px；提升暗色对比度，风险采用文字+颜色；手机折叠导航、抽屉焦点恢复与 Escape |
| 首页       | 保留 OpenGuard 粒子文字和发光光标；修复低动态模式下粒子未归位、桌面采样颜色恒为白色的问题                         |
| 代码维护   | 拆分 pages/components/services/hooks/types，加入运行时快照校验、测试脚本、拟定接口契约和第三方许可说明            |

样例可信度修正：Python 依赖定位到 requirements.txt；模型改为明确虚构的 DemoResearch-8B，不给真实模型套用未经证实的许可结论。Apache NOTICE 只呈现“需按版本和分发场景核查”，不由前端推断法律义务。

## 验证记录（2026-09-03）

- 16 项 Node 回归测试：统计、筛选、导出、输入预检、快照契约、存储损坏、演示状态、API 失败、访问确认、幂等请求头、204 响应、路由。
- 12 组隔离 Chrome 浏览器回归：完整演示流程、刷新与筛选保留、风险/证据对应、处理状态独立、复制失败、CSV/JSON、抽屉 Escape/焦点、图谱键盘、报告打印、异常场景、拦截 API 去重、响应式。
- 1440×900、1280×720、390×844 下检查概览、风险详情、资源、图谱、报告、新建扫描，无页面级横向溢出；截图人工检查。
- TypeScript 检查与生产构建；依赖兼容检查。
- API 测试使用拦截响应，不代表真实后端联调通过。未宣称完整 WCAG 认证、真机/投影设备验收或性能基准通过。

## 仍需团队配合

- 确认并实现 API_CONTRACT.md 中的服务接口、鉴权、上传限制与幂等语义。
- 真实扫描、取消、复扫验证、SSE、覆盖范围、历史差异比较不在本轮前端独立实现范围。
- 大型快照的服务端分页、汇总、性能预算待联调后处理；当前不拿一页数据充当总量。
- 团队复核首页、工作台视觉与样例文案，按协作流程决定是否提交到现有前端分支。

## 建议验收顺序

首页 → 载入固定演示 → 跳过等待 → 概览待处理卡片 → 风险详情 → 切换证据分类 → 图谱节点 → 资源过滤/CSV → 六章报告/JSON。
然后回到新建扫描，分别试“证据缺失/AI失败”和“部分扫描失败”，最后切换真实接口确认失败提示。
