# OpenGuard P0 威胁模型

状态：`DESIGN_BASELINE`

版本：`0.1`

范围：A2 公开 HTTPS Git 仓库与 ZIP 输入、安全文件清单，以及其进入后续扫描器前的边界。当前是设计产物，**尚未实现、尚未经过负面测试**。

## 1. 安全目标与非目标

### 1.1 安全目标

1. 不可信输入不能读取或覆盖扫描根目录之外的文件。
2. 不可信仓库不能触发目标代码、hook、filter、构建、包管理器或安装器执行。
3. Git 网络请求不能访问回环、私网、链路本地、保留、云元数据或其他非公网地址。
4. ZIP/Git 的时间、磁盘、内存、CPU、进程、文件数和内容规模受限，超限时失败关闭。
5. 不同扫描任务、宿主机、服务凭据、日志和最终报告相互隔离；输入内容只保留最小必要证据。
6. 成功、失败、取消和进程恢复路径均有临时目录清理；残留可发现、可隔离、可追踪。
7. 扫描器和依赖按锁定版本/摘要引入，升级受控，运行时默认无网络。
8. 所有安全失败映射到冻结的 P0 API/`ScanRun` 状态，不泄漏堆栈、绝对路径、凭据或完整第三方内容。

### 1.2 非目标

- 不判断目标项目是否包含漏洞、恶意代码或供应链后门；
- 不提供强对抗恶意代码的动态沙箱，因为 P0 不执行目标代码；
- 不支持私有仓库、OAuth、SSH、Git 凭据或任意 URL 抓取；
- 不保证安全删除能抵抗底层文件系统、SSD、快照或备份取证；
- 不把风险提示提升为法律、安全认证或“项目无恶意代码”结论。

## 2. 系统上下文与数据流

```text
不可信用户/浏览器
      |
      | Git HTTPS URL 或 ZIP
      v
[TB-1 API 接收与限流]
      |
      +---- Git ----> [TB-2 DNS/HTTPS/重定向/公网复核] ----> 公网 Git 服务
      |
      +---- ZIP ----> [TB-3 ZIP 预检/流式安全解压]
                           |
                           v
                 每任务独立临时目录
                           |
                 [TB-4 lstat inventory + SHA-256]
                           |
                 只读、无网络扫描副本
                           v
                 [TB-5 外部扫描器边界]
                           |
                           v
                 领域对象/证据/错误/报告
                           |
                 [TB-6 日志与公开输出边界]
```

`local` 是冻结 Schema 中的来源类型，但 A2 公共 API 不接收任意本地路径；它只保留给本地部署/测试，并需后续单独定义允许根目录。`.git` 元数据仅用于固定 revision，不进入扫描根。

## 3. 信任边界

| 边界 | 不可信侧 | 可信侧 | 必须保持的性质 |
|---|---|---|---|
| `TB-1` | 请求字段、文件名、MIME、ZIP 字节、URL | API 验证器和任务调度 | 请求级大小/速率限制、无凭据、稳定错误、不可由请求提高限额 |
| `TB-2` | 域名、DNS 响应、TLS 站点、重定向、Git 服务数据 | 受限 Git 获取器 | 仅 HTTPS 公网、每跳和连接前复核、TLS 主机校验、解析结果固定 |
| `TB-3` | ZIP central directory、本地头、路径、压缩流、元数据 | 流式解压器 | 规范化路径、类型拒绝、双重限额、CRC/实际字节核对、无链接 |
| `TB-4` | 物化后的文件树 | inventory/哈希与扫描副本 | `lstat`、不跟随链接、同根安全打开、稳定相对路径、不可变摘要 |
| `TB-5` | 文件内容、manifest、许可证文本、解析器输入 | ScanCode/Syft/自研解析器进程 | 无 shell、只读根、无网络、最小权限、资源/时间限制、版本锁定 |
| `TB-6` | 可能含密钥/个人信息/终端控制字符的路径和内容 | API、日志、HTML/JSON/CSV、材料 | 最小化、脱敏、结构化编码、HTML 转义、无绝对路径和堆栈 |
| `TB-7` | 第三方发行包、镜像、规则/许可证数据更新 | 构建和发布输入 | 官方来源、版本/摘要/签名、台账、复核、禁止运行时自动漂移 |

## 4. 受保护资产

| 资产 | 风险 |
|---|---|
| 宿主机文件、进程和账号 | 路径逃逸、命令执行、权限提升 |
| 其他扫描任务的上传内容和报告 | 跨任务读取、覆盖、缓存污染 |
| 环境变量、代理、云凭据、Git 凭据和服务配置 | SSRF、日志泄漏、扫描器外传 |
| 网络边界与内部服务 | 回环/私网/元数据访问、端口探测、DNS 重绑定 |
| 服务可用性 | 压缩炸弹、大仓库、文件数、慢网络、解析器耗尽 |
| 证据完整性和 provenance | 输入替换、重复覆盖、哈希不一致、版本漂移 |
| 日志、错误和导出材料 | 密钥、个人信息、绝对路径、第三方内容泄漏 |
| 扫描器、规则和依赖供应链 | 被篡改发行物、已知/未知解析器漏洞、自动更新 |

## 5. 攻击者与能力假设

攻击者可以：

- 提交任意 ZIP 字节、文件名、文件内容、压缩元数据和重复条目；
- 控制公开 Git 仓库的提交、分支、对象、文件树、`.gitattributes`、子模块和符号链接；
- 控制自己的 HTTPS 域名、DNS 记录、证书和重定向链，并在解析间改变地址；
- 构造超大、深层、稀疏、重复、畸形或高压缩比输入；
- 在路径、manifest、README 和许可证文本中放置 shell 元字符、终端控制字符、HTML/公式注入、伪密钥和真实密钥；
- 重复提交、并发提交、取消任务或诱发进程崩溃。

攻击者初始不能修改服务器管理员配置、锁定的镜像/依赖或内核，但第三方扫描器本身可能存在漏洞，因此不能把“只做静态扫描”当作完整隔离。

## 6. 攻击面

- `POST /api/v1/scans` 的 Git URL、ZIP 文件、multipart 元数据和幂等键；
- DNS、TLS、HTTP 重定向和 Git smart HTTP 交互；
- Git pack 解码、checkout、attributes、filter、submodule 和工作树条目；
- ZIP central directory、本地头、压缩算法、文件类型、文件名和解压流；
- 文件系统规范化、Unicode/case-fold 碰撞、链接、TOCTOU 和临时目录；
- manifest/许可证/README 等解析器与外部扫描器；
- 结构化错误、日志、证据片段、HTML/JSON/CSV 和演示截图；
- 依赖下载、镜像、规则数据、扫描器升级和构建流水线。

## 8. 控制策略摘要

### 8.1 Git 获取

- 只接收无凭据、无 query/fragment、默认 443 端口的公开 HTTPS 仓库 URL；
- 对初始域名、每次重定向和连接前解析的全部 A/AAAA 地址做公网校验；连接固定到已校验地址并保留原主机 TLS/SNI；
- 隔离 Git 配置/`HOME`，禁用凭据交互、hooks、templates、filters、LFS smudge、子模块、额外协议和运行时代理覆盖；
- 使用参数数组、浅克隆、单分支、无 tags，并施加时间、磁盘、进程和文件数限制；
- 工作树只允许普通目录/文件；P0 对符号链接、gitlink 和特殊条目失败关闭。

### 8.2 ZIP 解压

- 先验证 ZIP 结构和 central directory，再逐项规范化路径、类型和规模；
- 拒绝绝对路径、父级穿越、盘符/UNC、NUL、碰撞、加密、链接和特殊文件；
- 按元数据和实际流式字节双重计数，限制压缩包、总解压、单文件、条目数、路径、深度和压缩比；
- 在新建的每任务目录中以安全文件描述符逐级创建普通文件，不调用通用“extract all”；
- 不递归解压嵌套归档，校验 CRC，失败时删除整个任务目录。

### 8.3 扫描与输出

- inventory 通过 `lstat`/安全打开生成相对 POSIX 路径、size、mode 和 SHA-256；之后扫描只读副本；
- 不执行、编译、安装目标项目；外部工具不经 shell，使用固定二进制、参数数组和受控环境；
- 扫描器无网络、最小权限、只读根、独立临时空间和 CPU/内存/时间/进程/文件描述符限制；
- 日志只保留请求/扫描 ID、阶段、稳定错误码、计数和摘要；URL 路径和文件内容默认哈希/截断/脱敏；
- HTML 转义、CSV 公式前缀、终端控制字符处理属于下游 A6/F0 必须补充的安全门禁。

## 9. 剩余风险与接受条件

| 风险 | 当前处置 | 接受条件/责任 |
|---|---|---|
| 合法大型或含 symlink/submodule 的公开仓库被拒绝 | P0 偏向失败关闭 | Terra 做真实仓库可用性评估；若放宽，必须新增不跟随链接的复制层和 Luna 负面测试。 |
| Git/压缩/扫描器未知解析漏洞 | 版本锁定、无网络、最小权限和资源隔离 | Root 记录版本/摘要；Luna 做畸形输入回归；部署侧定期受控升级。 |
| DNS 验证到连接之间的竞态 | 每跳复核并固定已验证 IP | Terra 必须证明客户端实际连接固定；仅“解析后再请求主机名”不能通过。 |
| 不能识别所有秘密/个人信息 | 不记录原文、最小摘录、模式脱敏、公开前人工审计 | Luna/Owner 执行最终敏感信息审计；高风险材料保持受限。 |
| 临时文件无法取证级擦除 | 权限隔离、短生命周期、删除和启动清道夫 | 不在宣传中声称“安全擦除”；报告披露边界。 |
| A6/F0 输出注入尚未设计完成 | A2 先保留原始数据/展示边界 | Terra 在报告/前端实现前新增 HTML/CSV/URL 安全验收，Sol/Luna 审核。 |

任何一项 `SEC-A2-*` 未实现或负面测试失败时，A2 不得标记完成；任何一票否决级的敏感信息、侵权或安全问题不得以“已知限制”替代修复。
