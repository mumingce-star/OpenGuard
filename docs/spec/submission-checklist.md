## 1. 签核角色

- `Owner`：队长/共同权利人，负责身份、权属、授权和最终上传确认；
- `Root`：整体验收、GitHub 发布状态和最终文件清单；
- `Sol`：正式规则、评分证据、法律表述边界和一票否决风险；
- `Terra`：可运行性、部署、成果链接和演示版本；
- `Luna`：材料完整性、匿名、复现、格式、资源台账和敏感信息检查。

模型不得代替 `Owner` 对共同权利、单位授权、个人信息授权或最终上传作确认。

## 3. 文件与字段门禁

### 3.1 作品名称和简介

- [ ] `SUB-META-001` 名称不超过 20 字，简洁且与实际作品一致。
- [ ] `SUB-META-002` 简介不超过 300 字，按“问题-方案-实现-效果-开放成果”组织。
- [ ] `SUB-META-003` 简介中的每个效果数字和开放成果均已在 `report-evidence-map.md` 绑定证据；没有证据的内容改为计划或删除。

### 3.2 技术报告 PDF

- [ ] `SUB-PDF-001` 文件为可正常打开的 PDF，不超过 10 MB。
- [ ] `SUB-PDF-002` 正文建议控制在 15 页以内；如超过，已说明必要性且未将篇幅当作评分优势。
- [ ] `SUB-PDF-003` 资源清单作为附件存在，七组业务字段完整：名称及类型、版本/来源、许可证/授权类型、使用/开放方式、关键义务/限制、团队自主修改或开发内容、合规状态。
- [ ] `SUB-PDF-004` 九章覆盖与证据映射一致；所有图表、截图、指标、反馈、功能和链接能回到稳定 `claim_id`/`evidence_id`。
- [ ] `SUB-PDF-005` PDF 字体、图片、书签/链接、页码、裁切和表格经逐页渲染复核，无乱码、遮挡或失效链接。

### 3.3 演示视频

- [ ] `SUB-VID-001` 原则上提交 MP4，时长 3-5 分钟，大小不超过 300 MB。
- [ ] `SUB-VID-002` 清晰展示核心功能、操作流程、实现效果和开放成果；录屏版本与最终提交版本一致。
- [ ] `SUB-VID-003` 不展示虚构数据、未完成流程、密钥、个人目录、账号、浏览器个人信息、终端历史或无权公开内容。
- [ ] `SUB-VID-004` 音频、图片、字体、素材和背景音乐的来源与权利边界已登记。

### 3.4 成果链接与运行说明

- [ ] `SUB-LINK-001` 评审期内持续有效，使用无痕/未登录环境和不同设备验证。
- [ ] `SUB-LINK-002` 对需要运行环境的成果提供版本、依赖、安装、部署、运行、输入样例、预期输出和故障排查说明。
- [ ] `SUB-LINK-003` 公开仓库含 LICENSE、必要 NOTICE/第三方资源说明、测试入口和已知限制；链接指向冻结提交或发行版本。
- [ ] `SUB-LINK-004` 私有/受限链接仅用于正式允许的权利保护场景，访问方式已由 Owner 验证；不提交密码、API 密钥等无关凭据。

### 3.5 答辩和佐证材料

- [ ] `SUB-FINAL-001` 答辩 PPT 仅在晋级总决赛并收到通知后准备，提交格式为 PDF。
- [ ] `SUB-SUP-001` 佐证材料为可选，只纳入能支持具体评分项且可核验的测试、反馈、截图、提交或 Issue/PR 记录。
- [ ] `SUB-SUP-002` 不用专利、论文、企业合作、代码量或材料量替代核心评分证据。

## 4. 匿名、AI 和敏感信息门禁

- [ ] `SUB-ANON-001` 技术报告、视频、答辩 PDF 及其他评审材料无学校名称、学校 LOGO 和指导教师信息。
- [ ] `SUB-ANON-002` 项目内部加严：正文和截图使用成员 A/B/C 或匿名职能；清理作者、路径、终端提示符、Git 配置、截图菜单栏、PDF/图片元数据和链接落地页的可识别信息。
- [ ] `SUB-AI-001` 披露生成式 AI/智能体/自动化工具的用途、环节、输入范围、输出、团队修改、审核、验证、来源/权利核查和适用条款。
- [ ] `SUB-AI-002` AI 生成内容未被直接表述为团队当然享有的自主知识产权；AI 结论不能代替许可证原文或人工复核。
- [ ] `SUB-SEC-001` 仓库、提交历史、报告、视频、日志、截图、样例和压缩包中无真实密码、令牌、密钥、Cookie、私钥、连接串、个人信息、商业秘密或本机绝对路径。
- [ ] `SUB-SEC-002` 不公开无权再分发的第三方代码、模型、数据、素材或完整受限内容；只保留必要引用、哈希、URL、版本和授权状态。

## 5. 最终上传操作门禁

1. [ ] 冻结提交、规则版本、Bench 版本、报告版本和演示版本，记录 SHA-256/提交哈希。
2. [ ] 运行完整测试、部署烟雾测试、证据重算、匿名扫描、敏感信息扫描、链接检查和 `git diff --check`。
3. [ ] 从空环境按公开文档完成一次部署和固定样例扫描；保存脱敏 `run_id` 与结果。
4. [ ] 在不同设备、未登录浏览器中打开成果链接、下载报告、播放完整视频并检查音画同步。
5. [ ] Owner 逐项确认共同权利、单位/指导关系授权、第三方许可、受限公开边界和平台声明。
6. [ ] 在官方平台核对名称、简介、方向、附件、文件大小、链接权限和最终预览。
7. [ ] 在官方截止前提交，保存平台回执和时间；回执只存于受控材料区，不公开个人信息。
8. [ ] 截止后不再假设可以修改；任何组委会补正通知由 Owner 处理并保留原始通知与补正版本。
