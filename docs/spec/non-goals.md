# P0 非目标与边界

状态：`FROZEN_FOR_P0`

P0 优先交付可运行、可验证、证据可追踪的学生团队作品。以下事项不属于 P0 完成条件，不能为了“功能丰富”侵占安全、证据、测试、资源清单或演示主链。

## 1. 明确不做

| ID | 非目标 | P0 边界 | 原因/替代 |
|---|---|---|---|
| `NG-P0-001` | 企业级多租户合规平台 | 不做组织、租户、RBAC、计费、审计中心、SLA、分布式队列和 PostgreSQL 高可用。 | 比赛版单机部署；官方不要求企业级系统。 |
| `NG-P0-002` | 私有仓库 OAuth/凭据代理 | 不接收 GitHub/GitLab token、SSH key、用户名密码或 URL 凭据。 | 只接受公开 HTTPS Git；受限参赛材料与产品扫描入口分离。 |
| `NG-P0-003` | 漏洞/CVE、恶意代码和供应链攻击检测产品 | 不承诺 SCA 漏洞覆盖、木马识别、沙箱动态分析或安全认证。 | A2 只保护 OpenGuard 不被不可信输入利用；不评价目标代码是否安全。 |
| `NG-P0-004` | 自动法律意见或合规裁决 | 不输出“合法/违法”“可以商用/不可商用”等确定法律结论。 | 只做证据整理、规则触发、风险提示与人工复核建议。 |
| `NG-P0-005` | 训练或微调大模型 | 不采购专用硬件，不训练大规模模型，不以参数规模/算力作为成果。 | 使用锁版开放权重模型做有限辅助，并提供无 AI 降级。 |
| `NG-P0-006` | 执行、编译、测试或安装目标项目 | 不运行目标仓库脚本、hook、构建工具、包管理器、容器、宏或插件，不安装其依赖。 | 只做静态清单、受限扫描器和元数据解析。 |
| `NG-P0-007` | 私有/任意网络抓取 | 不支持 SSH、Git、HTTP、FTP、`file`、`ext` 等协议，不扫描内网、回环、链路本地或云元数据地址。 | 仅公开 HTTPS Git，执行每跳 SSRF 校验。 |
| `NG-P0-008` | 全语言、全生态和完整许可证兼容矩阵 | P0 只覆盖 Python、JavaScript/TypeScript 和优先 15 种许可证风险规则。 | 未覆盖资源显示 `unknown`/`review_required`，不伪装为通过。 |
| `NG-P0-009` | 第三方内容镜像与再分发 | 不打包无权再分发的仓库、模型、数据、许可证受限素材或用户上传项目。 | 真实样本只保存 URL、提交哈希、标注、许可状态和最小证据。 |
| `NG-P0-010` | 专利、权属或授权的自动确认 | 不替团队/权利人判断专利影响、共同权利份额、单位归属或最终公开授权。 | 工具提示待核验，Owner 完成最终签署。 |
| `NG-P0-011` | 在线协作与自动社区写入 | 不自动提交 Issue/PR、修改上游仓库、发送邮件或发布报告。 | 输出可审查建议和离线材料，由人决定外部操作。 |
| `NG-P0-012` | PDF 自动生成作为主链硬依赖 | P0 报告主链优先 HTML、JSON、CSV 和资源清单。 | 参赛技术报告由材料流程制作；若延期，产品 PDF 自动导出优先砍除。 |

## 2. 不可被非目标削弱的 P0 必做项

- Git/ZIP 安全输入、不可变 inventory、SHA-256 和临时目录生命周期；
- 软件、模型、数据集、API/服务四类资源及第一类 `Evidence`；
- 确定性事实与 AI 辅助分层，AI 关闭后主链仍可用；
- `pass`、`warning`、`review_required`、`unknown` 的诚实语义；
- HTML/JSON/CSV/资源清单、测试、OpenGuard-Bench 和可复现演示；
- 第三方资源台账、AI 辅助记录、匿名和权利边界审计。

## 3. 变更门禁

要把任一非目标纳入 P0，必须先写变更请求，说明评分收益、依赖、威胁模型、Schema/API 影响、测试、资源登记、材料证据和要砍除的等量范围，并由 Root、Sol、Terra、Luna 和必要的权利人确认。未完成变更门禁前，README、演示和报告不得把该能力写成已支持。
