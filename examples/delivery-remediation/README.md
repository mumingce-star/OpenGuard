# 手动明确依赖版本样例

本目录的演示文档和声明由本次 OpenGuard 开发编写，沿用仓库 Apache-2.0；没有第三方依赖源码或媒体。before/after 内的根 LICENSE 只用于本样例，不代表 requests 的许可。

1. 复制 before 到独立演示目录，压缩为 ZIP，通过真实扫描入口上传；保留 ZIP SHA-256 和扫描、评估、任务及报告 ID。
2. 在整改页从该评估明确派生任务，选择与版本/来源核验有关的任务，记录“准备手动明确 requests 版本；许可尚待核验”。如果真实评估未产生相关任务，不用不相关任务冒充，记录未满足并核查原因。
3. 手动将副本 requirements.txt 的 requests>=2.32.3 改为 requests==2.32.3；与 after 对照。此版本仅作静态输入，不是依赖版本推荐，不安装或执行。
4. 再压缩并真实上传，得到第二个扫描；保留两个输入及 SHA-256。允许的改善仅为声明的版本从范围约束变为精确版本，其他 pending/unknown 不变成通过。
5. 在差异页选择两个 ZIP，明确确认它们是自己的同项目输入，再读取既有 Diff。配对是用户声明；不是来源可信证明。页面不能自动把同名 ZIP 视为同项目。
6. 在旧任务填写实际修改、复扫 ID 和剩余许可缺口；生成新的固定报告。原扫描、原 Formal 结论、旧报告不被回写。

交付记录必须同时含输入摘要、真实 Evidence 原文、任务版本、两个扫描、Diff 和新报告，未完成真实运行时不得将该样例记作 F04 验收通过。
